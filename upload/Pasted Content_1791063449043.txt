# 4. A biblioteca de conhecimento merece atenção especial

Aqui está, provavelmente, o componente mais importante para um sistema jurídico realmente bom.

Em julho de 2026, a MinutaIA lançou aproximadamente **2.000 “Habilidades” jurídicas** cobrindo 25 áreas e centenas de formas de peças. [minutaia.com.br](https://www.minutaia.com.br/blog/habilidades)

Uma habilidade não é simplesmente um embedding.

Ela é, essencialmente:

```text
SKILL
│
├── identificação
├── título
├── descrição
├── área
├── subárea
├── tipo
│   ├── matéria
│   └── forma da peça
│
├── gatilhos
├── conteúdo jurídico
├── legislação aplicável
├── súmulas
├── precedentes qualificados
├── vigência
├── exceções
├── divergências
├── erros a evitar
├── versão
├── fonte
└── data de atualização
```

A arquitetura descrita por eles é particularmente inteligente.

O modelo **não recebe as 2.000 skills**.

Primeiro analisa apenas algo equivalente a:

```text
título + descrição + gatilhos
```

Seleciona as candidatas.

Depois carrega somente o conteúdo integral das skills selecionadas. A própria MinutaIA descreve isso como o equivalente a um advogado olhar as lombadas de uma estante e retirar apenas os livros relevantes. [minutaia.com.br](https://www.minutaia.com.br/blog/habilidades)

Em termos computacionais:

```text
caso
 ↓
classificador jurídico
 ↓
áreas prováveis
 ↓
retrieval das skills
 ↓
top-k skills
 ↓
reranking
 ↓
skills obrigatórias + opcionais
 ↓
contexto do agente
```

Isso economiza tokens e melhora precisão.

### Eu construiria exatamente esse conceito.

Mas não copiaria as skills da MinutaIA.

Criaria uma biblioteca jurídica própria, com proveniência e versionamento.

Por exemplo:

```yaml
skill_id: consumidor_negativacao_001
titulo: Inscrição indevida em cadastro restritivo
area: consumidor
subarea: responsabilidade_civil

gatilhos:
  - negativação
  - Serasa
  - SPC
  - cadastro inadimplentes

fontes:
  - CC
  - CDC
  - Sumula 385 STJ

regras:
  - verificar inscrição preexistente
  - verificar legitimidade do débito
  - analisar dano moral
  - distinguir cancelamento de indenização

erros_a_evitar:
  - citar precedente não validado
  - presumir dano moral em qualquer hipótese

vigencia:
  verificado_em: 2026-10-03
```

Isso transforma conhecimento jurídico em **software auditável**.

# 5. Skills não são RAG

Essa diferença é crucial.

Um sistema jurídico moderno deveria ter pelo menos três mecanismos separados.

| Camada | Utilização |
|---|---|
| RAG documental | descobrir fatos dos autos |
| Retrieval jurídico | recuperar legislação/jurisprudência |
| Skills | dizer ao agente **como raciocinar juridicamente** |

Embeddings sozinhos não resolvem isso.

Uma petição pode conter a expressão:

> “inscrição indevida”

O RAG encontra páginas do processo relacionadas.

Mas a skill deve dizer:

> analisar Súmula 385; verificar inscrição legítima preexistente; separar obrigação de cancelamento da pretensão indenizatória etc.

É uma camada diferente.

# 7. A MinutaIA tomou uma decisão correta contra “jurisprudência inventada”

A estratégia do JurisprudênciaIA é fundamental.

Segundo sua documentação, a IA não deve simplesmente escrever uma ementa como texto livre; ela referencia decisões efetivamente recuperadas. [MinutaIA](https://www.minutaia.com.br/blog/jurisprudenciaia?utm_source=chatgpt.com)

Eu usaria uma política ainda mais restritiva:

```text
LLM NÃO PODE CRIAR UMA CITAÇÃO JURISPRUDENCIAL
```

O redator receberia algo assim:

```json
{
  "source_id": "jur_394581",
  "tribunal": "STJ",
  "numero": "...",
  "ementa": "...",
  "url_oficial": "...",
  "verified": true
}
```

E poderia produzir apenas:

```text
{{JURISPRUDENCIA:jur_394581}}
```

Depois o backend substituiria esse marcador pela referência real.

Isso elimina praticamente toda a classe de alucinação de número de processo.

# 8. Referência rastreável de fatos dos autos

Outro mecanismo excelente é o sistema de **Referências Rastreáveis**.

Quando a IA afirma:

o sistema pode apontar diretamente:

```text
documento: contrato.pdf
página: 17
trecho: ...
bbox: x/y/w/h
```

A MinutaIA afirma permitir abrir a página exata do PDF e destacar o fragmento utilizado. [MinutaIA](https://www.minutaia.com.br/blog/referencias?utm_source=chatgpt.com)

Para criar algo equivalente, nosso banco deveria guardar a proveniência em nível de chunk:

```text
document_id
page_number
chunk_id
char_start
char_end
bbox
text
embedding
hash
```

Durante a geração:

```text
afirmação
→ source_id
→ document_id
→ página
→ fragmento
```

Essa é uma das funções que mais aumentam a confiança do advogado.

# 14. O editor também é parte da inteligência

A MinutaIA refez seu editor em 2026.

Cada parágrafo passou a ter **identidade estável**, o que permite que a IA modifique apenas um trecho, preservando o restante. [MinutaIA](https://www.minutaia.com.br/blog/novo-editor)

Isso sugere uma estrutura semelhante a:

```text
Document
 ├─ node_001 heading
 ├─ node_002 paragraph
 ├─ node_003 paragraph
 ├─ node_004 table
 └─ node_005 paragraph
```

Ao invés de salvar:

```text
document = giant_html_string
```

Isso permite:

```text
edit(node_003)
```

sem reescrever o documento inteiro.

É exatamente o tipo de arquitetura que eu recomendaria.

# 19. Segurança contra prompt injection

Esta parte merece ser copiada conceitualmente.

A MinutaIA descreveu publicamente uma defesa em duas camadas.

Antes da geração, analisa elementos anormais em PDFs como texto invisível, transparência, elementos fora da página e texto microscópico. Depois usa outro mecanismo de auditoria para detectar desvio das instruções. [MinutaIA](https://www.minutaia.com.br/blog/prompt-injection?utm_source=chatgpt.com)

O princípio que deveríamos adotar é:

```text
DOCUMENTO = DADO NÃO CONFIÁVEL
```

Nunca:

```text
DOCUMENTO = INSTRUÇÃO
```

O pipeline deveria distinguir explicitamente:

```text
SYSTEM INSTRUCTIONS
USER INSTRUCTIONS
TRUSTED SKILLS
TRUSTED SOURCES
UNTRUSTED DOCUMENT CONTENT
```

Isso é fundamental em IA jurídica.

# 20. Anonimização local

O tarja-1 é tecnicamente muito interessante.

Ele anonimiza dados **localmente**, substituindo, por exemplo:

```text
Maria da Silva
CPF 123...
```

por:

```text
[NOME_0001]
[CPF_0001]
```

A IA trabalha apenas com marcadores.

Depois o computador do usuário restaura os dados originais. [MinutaIA](https://www.minutaia.com.br/blog/tarja-1)

O cofre fica local.

Arquiteturalmente:

```text
Documento
   ↓
local NER
   ↓
pseudonimização
   ↓
[NOME_001]
   ↓
cloud AI
   ↓
[NOME_001]
   ↓
cofre local
   ↓
nome real
```

É excelente para segredo de justiça.

```text
norma
artigo
paragrafo
inciso
alinea
vigencia_inicio
vigencia_fim
alteracoes
fonte_oficial
hash
```

Isso permite responder:

> “Qual era a redação vigente na data do fato?”

Esse recurso seria superior a grande parte das IAs jurídicas atuais.

# 24. Governança e LGPD

A própria política da MinutaIA informa não utilização de autos ou minutas para treinamento e tratamento temporário de documentos, além de possibilidade de biblioteca quando expressamente escolhida pelo usuário. [MinutaIA](https://www.minutaia.com.br/politica-de-privacidade?utm_source=chatgpt.com)

Para um produto nosso, LGPD não pode entrar no final.

Precisa entrar no modelo de dados.

A Lei 13.709/2018 exige medidas de governança compatíveis com natureza, volume, sensibilidade e riscos do tratamento. [Planalto](https://planalto.gov.br/ccivil_03/_ato2015-2018/2018/lei/l13709compilado.htm?utm_source=chatgpt.com)

Além disso, se a solução for usada dentro do Poder Judiciário, a Resolução CNJ 615/2025 — posteriormente alterada pela Resolução 674/2026 — estabelece requisitos próprios de governança de IA. [Atos CNJ](https://atos.cnj.jus.br/atos/detalhar/6001?utm_source=chatgpt.com)

Precisaremos desde a primeira versão de:

```text
tenant isolation
RBAC
audit log
provenance
encryption
retention rules
data deletion
provider policies
human review
model/version log
prompt/version log
```

# 31. Minha conclusão

Depois deste levantamento, minha leitura é:

**não precisamos descobrir ou copiar o código da MinutaIA para construir algo equivalente.**

Já conseguimos identificar a maior parte de sua **arquitetura conceitual**.

O produto pode ser resumido assim:

```text
                    MINUTA-LIKE
                        │
        ┌───────────────┼───────────────┐
        │               │               │
      AUTOS          CONHECIMENTO     USUÁRIO
        │               │               │
     fatos           skills           estilo
     provas         legislação        modelos
     páginas       jurisprudência    preferências
        └───────────────┼───────────────┘
                        │
                  AGENTE JURÍDICO
                        │
             planeja → pesquisa
                        │
               consulta ferramentas
                        │
                 cria estratégia
                        │
                  gera roteiro
                        │
                 redige seções
                        │
                  verifica tudo
                        │
                    RED TEAM
                        │
                      EDITOR
                        │
                   DOCX / PDF
```

E o componente mais valioso, na minha avaliação, **não é GPT, Claude ou Gemini**. São quatro elementos trabalhando juntos:

**skills jurídicas versionadas + recuperação híbrida de fontes + rastreabilidade factual + orquestração agêntica com supervisão humana.**

Para o seu caso, eu não criaria necessariamente um segundo ecossistema jurídico separado. A estrutura pode ser incorporada como o **núcleo de inteligência jurídica do EJC**, aproveitando clientes, casos, processos, documentos e RAG que já existem e construindo por cima a camada tipo MinutaIA. Isso reduziria bastante duplicação e faria o EJC evoluir de ERP jurídico com IA para uma verdadeira plataforma de produção e raciocínio jurídico. 

O próximo trabalho que vale a pena fazer é **transformar esta engenharia reversa funcional em uma especificação técnica completa do nosso sistema**, incluindo banco de dados, tabelas, APIs, serviços, agentes, skills, fluxo de processamento de documentos, engine jurisprudencial, editor, modelo de segurança e uma sequência de implementação por módulos. Isso já pode virar o projeto executivo para começar o desenvolvimento.
